# 명찰 제작기 검증 기록

검증일: 2026-10-26. 가상 명단만 사용했다. 원본 참고 소스와 자산의 근거는 `badge-shared/design-provenance.md`, 삽입지 규격은 `badge-shared/README.md`에 기록했다.

## 검증한 기능

- `node tests/badge-core.cjs`: 17개 통과. A4 배치 경계, 여백·간격, 장수·순서, 인용부호·줄바꿈·BOM CSV/TSV, 입력 크기 제한, 수식 보호, JSON 버전·범위·중복 ID·프로토타입 검증.
- `node tests/badge-browser.cjs`: 88개 통과. Windows의 별도 임시 프로필 Edge를 사용했다. 1440×1050과 390×844 화면, 다섯 템플릿, 실시간 편집, HTML 문자 안전성, 실제 CSV 다운로드·파일 읽기, 빈/잘못된 가져오기 시 기존 명단 보존, JSON 파일 저장·복원, 방향 전환, 인쇄 불가 크기 차단, 사용법, 외부 요청 및 자동 저장 없음.
- 다섯 템플릿에서 명찰 실제 가로·세로, A4 경계, 명단 순서와 재단선 8개/명찰을 확인했다.
- 목걸이 95×122 mm, 여백 8 mm·간격 3 mm: 2열×2행, 9명 → 3장. 집게 90×54 mm: 2열×4행, 17명 → 3장.
- 각각 선택한 2명 → 1장, 100 mm 시험 자 → 1장. PDF MediaBox가 A4인지 확인했다. 생성된 PDF를 pypdf로 다시 읽어 정확한 인원·순서를 확인하고 Poppler로 모든 샘플 페이지를 렌더링해 시각 검수했다.
- 별도 검토에서 95×65, 90×54, 75×40, 54×85 mm × 다섯 템플릿의 기본 문구 잘림 없음, 인쇄/화면의 공식형 경계 일치, 작은 규격의 잘림 차단과 일반 인쇄 복원을 확인했다.

## 재실행

브라우저 검사는 `playwright`, `pdf-lib`가 필요하다. 환경에 설치된 Chromium 경로를 `BADGE_BROWSER`로 지정할 수 있다. Windows 기본값은 Edge다. 테스트는 자체 임시 로컬 서버를 열며 기존 브라우저 프로필이나 탭을 사용하지 않는다. 결과는 저장소 밖 형제 `evidence/`에 저장한다. `BADGE_BASE_URL`을 지정하면 같은 검사로 공개 사이트를 검증할 수 있다.

## 기존 기능의 기준 상태

기준 main: `d9e4fdee01cf7c4890ac7210ab762bb525b5b354`.

- 기존 로고 검사, NOW 75개 검사, 면접 도구 95개 검사 통과.
- 기존 `tests/search-recovery.cjs`는 전체 프로젝트 수를 28개로 가정하지만 기준 소스에는 29개가 있다.
- 기존 `tests/work-tags.cjs`는 서로 다른 소스 구간을 비교하는 기준 실패가 있다. 해당 테스트나 기존 기능은 수정하지 않았다.
- 카드 등록은 공개 앱 확인 이후 별도 변경으로 수행하며 기존 카드·숨김 18번·사용법·NOW·문의 폼 보존을 전용 검사로 확인한다.

## 한계

실물 프린터 출력, 프린터 드라이버의 배율·급지 오차, 특정 홀더의 실제 적합성은 미검증이다. 앱 사용법은 먼저 100 mm 눈금을 시험 출력하도록 안내한다. 시스템 글꼴을 사용하므로 기기별 글자 모양 차이가 있을 수 있다. 운영 의견 접수 endpoint는 이 구현 시점에 전달되지 않아 동작하지 않는 접수 버튼을 넣지 않았다.
