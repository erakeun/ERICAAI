# PROJECT MACH · 면접 준비 원큐 V0.1

대학 면접의 일정·장소·면접위원·지원자 배정부터 질문·평가·안내·당일 운영·결과 확인·출력까지 관리하는 정적 웹앱입니다. 지원자를 평가하거나 합격자를 추천하는 AI 기능은 없으며, 결과는 담당자가 직접 입력하고 확정합니다.

**운영 주소:** [면접 준비 원큐](https://erakeun.github.io/ERICAAI/interview-oneq/)
**배포 상태:** 기존 PROJECT MACH GitHub Pages 배포 및 운영 URL 재검증 완료. 세부 결과는 [최종 검증 기록](validation/FINAL-VALIDATION.md)에 있습니다.

## 사용 순서

1. **새 면접 만들기**에서 유형을 선택하고 모집분야·담당자·준비물·문의처를 입력합니다. **지난 면접 설정 가져오기**는 지원자·평가·결과를 제외하고 설정을 복제합니다.
2. **일정·장소**에서 날짜·오전/오후·면접실별 회차(Session)를 만듭니다. 실제 면접시간과 장소 사용시간, 대기실·접수 위치·휴식·면접 방식을 설정합니다.
3. **면접위원**을 등록하고 회차별 참여를 지정합니다. **지원자 명단**은 직접 입력·붙여넣기·CSV·Excel로 등록할 수 있으며 번호를 자동 생성합니다.
4. **시간 시뮬레이션**에서 가능·불가시간과 고정·잠금을 반영해 자동배정합니다. 미배정·충돌을 해결하고 시간표를 확정합니다. 정원이 부족해도 면접시간을 줄이거나 종료시간을 넘겨 배정하지 않습니다.
5. **질문·평가표**를 수정하고 **지원자 안내**의 문구를 복사합니다. 생성·실제 발송확인·회신확인을 따로 기록합니다. 확정 후 시간·장소 등이 바뀌면 재안내를 표시하며, 배정이 무효가 된 경우 확정을 해제합니다.
6. **출력 센터**에서 A4 자료를 준비하고 기존 MACH 제작기용 JSON을 저장합니다. **현장 운영**에서 도착·대기·면접 중·완료·지각·결시 등을 기록합니다.
7. **평가·결과**에서 점수를 저장하고 누락을 확인합니다. 미입력과 입력된 0점은 구분됩니다. 담당자가 합격·예비합격·불합격 등을 정한 뒤 검토 확인을 거쳐 결과를 확정합니다.
8. **저장·변경이력**에서 프로젝트별 또는 전체 JSON 백업을 보관합니다.

## 제공 기능

- 학생단체·근로학생·서포터즈·조교/연구보조·직원/계약직·기타의 6가지 편집 가능한 기본 설정
- 여러 날짜·회차·위원·면접실, 개인면접·조별면접, 휴식과 분야·가능시간·불가시간 제약, 수동 이동과 고정·잠금
- 질문은행 11분야 44개 예시, 질문 수정·추가·선택, 평가항목·배점·기준 수정, 8개 안내 템플릿
- 현장 상태, 번호 중심 대기실 화면, 위원별 평가 누락·합계·평균, 담당자 결과 확인, 예비순번
- **9종 출력:** 지원자별 평가표, 면접위원용 패킷, 운영자용 패킷, 접수·출석 자료, 전체 면접시간표, 질문지, 평가기준표, 현장 게시자료, 결과 검토자료
- A4 세로·가로, 지원자별 평가지 페이지 분리, 반복 표 머리글, 문서 버전·출력시각, 독립 HTML 저장
- 브라우저 저장, JSON 백업·복원, 설정 복제, 변경이력, 오래된 출력 경고, 다른 탭의 저장 변경 감지

면접 8분+평가·교체 2분은 10분 슬롯입니다. 조별 3명/20분은 그룹 전체가 한 20분 슬롯을 사용합니다. 현장 상태를 바꿔도 면접시간이나 합격 여부가 자동으로 바뀌지 않습니다.

## 기존 MACH 도구 연동

연동은 생성한 JSON을 기존 제작기의 파일 가져오기로 여는 방식입니다. 제작기의 현재 작업은 먼저 저장하세요.

| 도구 | 사용 방법 |
|---|---|
| [명패 제작기](https://erakeun.github.io/nameplate-maker/) | 기본 **새 면접 명패 작업** JSON은 제작기의 **작업 불러오기**로 엽니다. 같은 면접 디자인을 유지한 명단 갱신은 **같은 면접 명단 갱신** JSON을 **변경분 JSON 가져오기**로 검토·반영합니다. |
| [안내문 제작기](https://erakeun.github.io/notice-maker/) | 회차·면접실/대기실/접수처·방향 문구를 고른 JSON을 **작업파일 불러오기**로 엽니다. |
| [디지털 제작기](https://erakeun.github.io/digital-signage-maker/) | 면접명·날짜·시간·장소 JSON을 **작업파일 불러오기**로 엽니다. |
| [ERICA 캠퍼스맵](https://erakeun.github.io/erica-campus-map/) | 실제 52개 건물에서 선택하면 해당 건물 ID를 담은 위치 링크와 QR을 만듭니다. 운영 지도 수신 코드의 배포·재검증 상태는 최종 검증 기록을 따릅니다. |

명패에는 위원 이름·소속·직위·역할만, 안내문에는 면접명·일시·장소·안내 문구를 전달합니다. 지원자 명단·연락처·평가와 위원 연락처는 제작기 파일에 포함하지 않습니다. 유효하지 않은 건물 ID는 지도 기본 주소로 연결합니다. 실제 명패 수신 코드의 출처는 [수신 계약 자료](tests/fixtures/README.md)에 기록했습니다.

## 저장·운영 범위

- 데이터는 현재 브라우저의 `localStorage`에 저장됩니다. 저장 키는 `mach:interview-oneq:v1`입니다. 기기·브라우저·주소가 바뀌면 자동으로 이어지지 않습니다.
- 계정·서버 DB·공동운영·기기 간 자동동기화·실제 SMS/이메일 발송·지원자용 온라인 회신 수집은 제공하지 않습니다. 안내 발송확인은 담당자가 실제 발송 후 기록하는 상태입니다.
- 입력·CSV/Excel 읽기·QR 생성은 브라우저에서 처리합니다. 앱 자체가 지원자 정보를 서버로 전송하지 않습니다. 브라우저 데이터 삭제·시크릿 모드 종료·저장용량 초과에 대비해 JSON 백업을 보관하세요.
- 백업과 내부용 출력물에는 개인정보가 들어갈 수 있습니다. 기관의 보관·공유 기준에 따라 관리하세요. 복원 시 같은 프로젝트 ID는 교체 전 백업을 저장하고, 다른 프로젝트는 유지합니다.
- Excel은 첫 시트의 저장된 표시값을 읽으며 수식을 새로 계산하지 않습니다. 가져오기 파일은 10MB, 프로젝트당 지원자는 5,000명까지이며 실제 용량은 브라우저·기기에 따라 제한됩니다.
- 면접·휴식은 같은 날짜 안에서 설정합니다. 자정을 넘는 운영은 날짜별 회차로 나눕니다. 모집분야 제한은 지원자 분야명과 정확히 일치해야 합니다.
- 평가표는 항목 10개·항목명 80자 이내입니다. 긴 자유 입력은 추가 페이지가 생길 수 있습니다. A4·배율 100%·브라우저 기본 머리글/바닥글 끄기를 권장합니다.
- 인쇄창·파일 생성은 실물 출력완료가 아닙니다. 실물 프린터·실제 휴대전화 QR 스캔·실기기 브라우저는 현재 환경에서 **미검증**입니다.

## 로컬 실행과 자동 테스트

이 폴더에서 Python 3와 Node.js/npm을 사용합니다. 앱 런타임 라이브러리는 `vendor/`에 포함되어 있어 `npm install` 없이 실행합니다.

```sh
npm start
```

[로컬 실행 주소](http://127.0.0.1:4183/)를 열고, 서버 종료는 실행 터미널의 `Ctrl+C`를 사용합니다. 상위 폴더에서 서버를 실행했다면 실제 하위 앱 경로로 접속합니다. `index.html`을 파일로 직접 여는 방식은 ES module 때문에 지원하지 않습니다. `localhost`, `127.0.0.1`, 다른 포트는 각각 별도 저장공간입니다.

```sh
npm test
```

보조 브라우저 회귀의 Playwright/Chrome 환경과 실행 방법은 [자동 검증 안내](tests/README.md)를 참고하세요. 실제 사용자 프로필을 사용하지 않고 가상 데이터만 생성합니다.
